## 配布用スキルのレビュー後の更新

利用者の説明・確認を受け、必須なのは対象成果版・fixtureの特定と独立照合であり、PythonやID生成スクリプトの利用は実行agentが判断する任意の手段であることを、原稿と配布スキルへ明記しました。不使用時の版参照・保存物・内容比較の経路、未照合部分の報告も追加しました。

続く再構築で、配布用の任意ツール`artifact_identity.py`を追加しました。旧試作は研究資料として扱い、固定Markdown解析・実行記録の追記・試験結果の判定は移植していません。スクリプトは [skills/fm-dev-process/scripts/artifact_identity.py](../../skills/fm-dev-process/scripts/artifact_identity.py)、利用方法は [artifact-identity.md](artifact-identity.md)、配布側は [skills/fm-dev-process/references/artifact-identity.md](../../skills/fm-dev-process/references/artifact-identity.md) を参照してください。

新方式はファイル別SHA-256とパス・サイズの正準JSONを集約し、旧方式のファイル境界の曖昧さを解消します。新旧IDは互換ではありません。補助ツールの使用とテスト要件は[ツールの説明](artifact-identity.md)および対応するSkillに従ってください。

## 補足

- **01〜05**: 成果物の定義と cheatsheet / 事前調査 / レビュー資料の枠組みづくりが中心。
- **06〜08**: 保存構成（suffix 規則）、技術選定の最小検証、ドメイン知識の整理という「実装品質を上げるための補完」が中心。
- **09〜12**: 規範の大きな改訂（ティア・ライトプラン・受入・worklog）と、本書自体を skill 化するための整備（重複整理、skill 化規約・手順）が中心。
- **13〜15**: 人間が読む説明（読む順路・人間向け説明の書き方）と、要求の根拠の境界（品質改善目標の禁止）、受入と plan 完了の分離（`accepted` / `done`）が中心。
- **16〜17**: 16で単一完全版を3階層（Lv.1 / Lv.2 / Lv.3）と共通資料2本＋役別プロンプト12本へ再構成。17で承認済みレビュー提案を原稿へ反映。旧版の `01_process.md`〜`15_process.md` は現在このリポジトリには同梱していない。

版16以降は各版の主要な変更点を要約しています。過去の討議記録、レビュー履歴や検証用資料は、明記がない限り本リポジトリには同梱していません。
