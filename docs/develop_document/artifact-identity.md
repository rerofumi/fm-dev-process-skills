# 任意の成果版・fixture同一性確認ツール

`scripts/artifact_identity.py` は、指定したファイル集合の機械IDを記録し、別担当が同じ内容を見ているか照合する補助手段です。**利用は実行agentの判断で任意です。** 使わない場合も、環境宣言に版参照・保存物・内容比較等の方法と確認範囲を残してください。Pythonの追加導入を基本スキルの開始条件にしません。

使う場合だけPython 3.10以上が必要です。外部Pythonパッケージ、Git、jj、ネットワーク接続は不要です。実行には利用先のuv・mise等の環境管理方針を使ってください。以下は既存のPythonをuv経由で実行する例です。`/path/to/skills`を実際の配置先へ置き換えます。

## 担当間での使い方

1. 対象範囲を合意し、作業を止めた対象ソース・成果物・fixtureから記録を作ります。ビルド出力や設定も結果に影響するなら含めてください。ソースを指定しただけでは生成バイナリを同定しません。
2. JSONを証跡として保存し、環境宣言と試験記録から参照します。試験ごとに、その実行が指すJSONと完全長の`identity`を記録してください。ソースとfixtureを別々に記録しても構いません。
3. 受入担当は記録された範囲が合意と合っているか確認し、自分が見ているコピーに対して`verify`を実行します。JSON内の`include`が採取範囲です。ID文字列の比較で範囲確認を省かないでください。
4. 変更時は新しい名前のJSONを作り、変更履歴と影響を受ける試験に対応付けます。旧記録の上書きや再採取だけで旧試験を有効にしません。

試験開始前の記録と終了後の照合を使う場合も、試験中に対象が変わらないようにしてください。ツールは試験を実行せず、試験中の一時的な変更や試験の実行事実を証明しません。

## 記録する

利用先プロジェクトのルートで実行します。出力先の親ディレクトリは事前に用意してください。

```sh
uv run --offline python /path/to/skills/fm-dev-process/scripts/artifact_identity.py snapshot --root . --include "src/**" --include "tests/fixtures/**" --output evidence/identity-r1.json
```

JSONを標準出力にも返します。`--output`を省略するとファイルは作りません。既存ファイルは上書きしません。改訂には`identity-r2.json`等の別名を使ってください。出力ファイルが自身の採取範囲に入る指定も拒否します。保存失敗で不完全な新規ファイルが残る可能性がありますが、成功とは報告しません。既存の記録には触れません。

必要なら`--expect-count 12`を加え、合意した一覧等に由来する件数と照合できます。件数だけでは同一性になりません。採取全体または個々の`--include`が0件ならエラーにし、globの誤記を成功へ丸めません。対象資産がない案件は、空集合を渡さず環境宣言に理由を書いてください。

## 独立に照合する

```sh
uv run --offline python /path/to/skills/fm-dev-process/scripts/artifact_identity.py verify --root /path/to/reviewer-copy --snapshot evidence/identity-r1.json
```

`--snapshot`は現在の作業ディレクトリからのパスで、`--root`からの相対パスではありません。照合ではJSONと対象ファイルを読み取り、書き換えません。コピー先の絶対パスが違っても、ルートからの相対パスと内容が一致すれば照合できます。

出力はJSONです。`status`、期待ID・実測ID、実測件数、採取範囲、追加・削除・変更ファイルを返します。

| 終了コード | 意味 |
| --- | --- |
| `0` | `snapshot`: 採取成功。保存指定時は読み戻しも一致。`verify`: 宣言された範囲が一致 |
| `1` | `verify`: ファイルの追加・削除・内容変更による不一致 |
| `2` | 不正入力、未知方式、0件、取得不能、採取中の変更、保存失敗等。比較不能 |

ある`include`に一致するファイルがすべて消えた場合は0件エラーの`2`です。不一致と取得不能をどちらも成功へ読み替えないでください。`0`も試験合格や受け入れ合格ではありません。

## 環境宣言への記録例

```text
対象参照: evidence/identity-r1.json / identity: sha256:<64桁の完全長>
対象範囲: プロジェクトルートから src/** と tests/fixtures/**
特定・照合方法: artifact_identity snapshot / verify
使用手段: artifact_identity 1.0.0（任意ツール）
機械ID方式: sha256-canonical-file-list-v1
照合結果: 受入担当が自身のコピーにverifyを実行。対象N件、一致。
未照合: 宣言範囲外の設定、OS・実行環境等。
```

JSONにはスクリプト自身の版・SHA-256も入ります。試験記録には別途実行ID・操作・結果・出力への参照を残してください。ツールはMarkdownの宣言や実行記録を解析・追記せず、判定語彙も変更しません。

## 方式と範囲

- 相対パスは`/`区切りです。`--include`は複数指定でき、重複ファイルは1回だけ採取します。`*`・`?`・`[]`は1階層、`**`は0階層以上です。全OSで大文字小文字を区別します。絶対パス、`..`、バックスラッシュ、`a**`のような部分的な`**`は拒否します。
- バイト列をそのままSHA-256へ渡します。改行・Unicode・パスの大文字小文字は正規化しません。改行変換のあるチェックアウトは不一致になります。権限・mtime・実行環境はIDに含めません。
- ファイルごとの`path`・`size`・`sha256`を相対パス順に並べ、`{"algorithm":"sha256-canonical-file-list-v1","files":[...]}`をPythonの`json.dumps(ensure_ascii=True, sort_keys=True, separators=(",", ":"))`でASCII符号化し、そのSHA-256に`sha256:`を付けます。末尾改行は集約計算に含めません。採取範囲・件数・ツール版等はJSONの別フィールドです。別実装でIDを生成するならこの方式に合わせます。
- schemaは`fm-artifact-identity-v1`です。旧`env_manifest_check`の指紋とは互換性がありません。移行時は新規採取と必要な試験の対応確認を行い、旧IDを新方式として比較しません。
- 採取対象のシンボリックリンク・junction等は辿らずエラーにします。通常ファイルを持つ安定したコピーを使ってください。採取中の一覧・サイズ・更新時刻等の変化を検出しますが、ファイルシステムの原子的snapshotを作るものではありません。
- JSONの内部整合は検査しますが、署名や改ざん検知の信頼基盤ではありません。JSONと試験記録自体は確認済みの版で保存・引き渡してください。対象範囲が狭すぎることや、根拠の文章が主張を裏付けるかは独立担当が確認します。
