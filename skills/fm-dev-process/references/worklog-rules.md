# 任意の worklog

## 91_worklog.md — 任意の判断経緯

新規Light / Fullでは `91_worklog.md` を既定で作成せず、90へ `worklog: disabled` と記録してください。判断経緯を別途追跡する必要がある場合、利用者が希望した場合、または既存計画の設定を継承する場合に限って `enabled` とし、90へ選択を記録します。既存の回答を継承してください。無効なら91を作らず、判断は50またはLightのnotesへ残してください。

有効なら、意味のある調査・要求整理・設計・レビュー・実装・受け入れ・文書反映ごとに、日時、対象、入力、行ったこと、根拠、決定・未決、成果物への参照を簡潔に残してください。新構成では固定された旧工程番号の消化を求めないでください。

実装・デバッグの記録は、`症状 → 仮説 → 修正 → 確認` の4行を基本に簡潔に残してください。help要請（症状 / 試したこと / 疑っている外的要因 / 無効になった資産の4行と再現コマンドへの参照）も同じ形式で残します。協議を経て方針を変えた場合は「方針転換」の1行（決めた方針・理由）を追記してください。デバッグの試行の全ログは残さないでください。1回目の失敗時点の1行の状況報告は、4行証跡とも help の4行とも別枠の任意の記録として残してください。help として数えないでください。

会話全文、長い実行ログ、秘密情報、要求や状態の複製は入れないでください。91は経緯を読む補助資料で、90や要求・仕様の正本に代わるものではありません。`92_replan.md` は初版では作らず、将来詳細を分けても現在の状態は90に保ってください。
## 記録のタイミングと形式

有効化したら開始時に選択と対象を記録し、意味のある作業・重要な判断が終わった時点で追記してください。後から記憶だけで全履歴を再構成しないでください。以前の記録は残し、訂正や変更は新しい項目から更新先を参照してください。

```text
WL-ID / 日時 / 担当 / 工程・対象:
目的 / 入力・参照した根拠:
行ったこと / 更新成果物:
決定と簡潔な理由 / 見送り・保留:
未決・影響 / 次への引き渡し:
```

記録するのは他の人が確認できる判断の要約と根拠です。内部の推論過程の逐語的な記録を求めないでください。Lightでは関連する作業をまとめられます。文書の量や旧ステップ番号を満たすための項目は作らないでください。
